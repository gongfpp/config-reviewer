# 定时自动评审的体验验收

本轮目标来自用户对「定时 Git 拉取后扫描最新文件、自动评审保存历史、移除 800 个文件限制、显示 400 / 589 一类进度」的要求。以下记录区分实现、可观察结果和仍需现场验证的条件。

| 核心体验目标 | 可观察的验收条件 | 当前证据 |
| --- | --- | --- |
| 简单设置后自动处理新资料 | 在 UI 保存目录和分钟间隔，到期自行拉取新提交，模型请求包含新文件内容，报告进入历史 | 本地后端与前端交互检查通过；Windows 安装后验证待补 |
| 关窗仍能运行 | 原生关闭窗口后窗口隐藏、进程保留；无需手动执行，到期生成新报告 | Windows 后台定时验证待补 |
| 完全退出后停止 | 从托盘退出后不再保留应用调度进程，运行中 Git 获得取消并清理子进程 | 退出清理已实现；真实托盘菜单操作待补 |
| 文件较多仍能全部处理 | 导入 805 个文件显示 805 / 805，9 页清单最后一页包含第 805 个文件 | 本地超 800 文件回归通过；Windows UI 验证待补 |
| 看清真实进度 | 发现阶段显示累计数量；已知总数后显示已完成 / 总数，扫描、解压、评审分别计数 | 本地浏览器模拟 IPC 检查 400 / 589；真实 Windows 过程待补 |
| 重启后计划和报告仍在 | 保存计划、执行后重启，目录、间隔、状态和历史均保留；删除计划保留报告 | 本地持久化回归通过；Windows UI 验证待补 |

硬约束：不恢复文件数量硬上限；不静默覆盖 Git 本地修改；不把未实际执行、无变化跳过或失败标成评审成功；API Key 沿用系统凭据库。真实内网数据和凭据不进入公共截图或构建材料。

用户已明确选择：自动执行「Git 拉取 → 扫描 → 评审 → 保存历史」；关闭窗口留在托盘，彻底退出后停止。因此应用必须在电脑上运行，休眠或关机时不会执行。未批准降低其他体验目标。

验证环境采用 Windows Server 2022 公共构建机、已安装应用、真实本地 Git 仓库与模拟 HTTP 模型服务。这用于验证自动化路径和 UI，不代替目标 Windows 10 的 Git 登录、托盘策略、网络或模型质量验收。模拟服务属于测试条件，不是对产品目标的技术折中。
