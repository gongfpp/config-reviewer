# 内网 Windows 桌面端「配置评审台」需求文档 v1.3

> 来源：`alert-bridge`（讯流）Android 端「内容评审」模块，内置 `XXL-JOB 配置评审` 等模板。
> 本工具把「配置评审」主线迁移到**内网 Windows 桌面端**，输入从「截图 + 视觉模型」改为
> 「混合发布包 / 文档 + 内网文本 LLM」，支持批量扫描、按模块路由模板、按模块分组出结论与导出。

---

## 1. 背景与目标

- 面向内网运维 / 测试 / 发布人员，对**发布包或指定目录**做上线前 AI 评审。
- 典型输入是一个 **ZIP 混合包**，内部可能同时（也可能没有）包含：
  - Apollo 的配置 JSON
  - XXL-JOB 的标准模板 Excel（或 Word 操作手册）
  - 星云配置文件夹
  - 其他杂项文件（README、pom.xml、图片等，通常跳过）
- 内网无 OCR、无视觉模型，统一使用**内网文本 LLM 网关**（OpenAI 兼容 + 流式），模型由用户自行配置。
- 桌面端：大屏、可批量、可导出、结果可读。

### 非目标

- 不直连 XXL-JOB Admin / 发布系统做真实变更。
- 不做移动端；不做多人在线协同（本机为主，导出分享）。

## 4. 解析、分块与引用规则

### 4.1 解析边界

- **Excel**：公式取**缓存计算值**；空 Sheet 跳过；超宽表截断并标注。
- **Word**：解析**段落 + 表格**；页眉页脚可选（默认关）；批注默认不含。
- **JSON**：格式化输出；解析失败时降级为纯文本，不中断。
- **编码**：UTF-8 优先，GB18030 回退。

### 4.2 分块

- 触发阈值与单块大小可配置（默认阈值 12000 字符、单块 8000 字符）。
- 切块单位按类型：Excel 按 Sheet / 行；Word 按段落；**JSON 顶层键优先**，单键仍超限再按字符；文本按行 / 字符。
- 分块后由 LLM 二次汇总为文件结论；各块结论保留可展开。

### 4.3 引用结构

- 固定结构：`{文件路径, 定位, 片段}`；片段截断约 120 字；每条风险可带多条引用。
- 定位按类型：Excel → `Sheet1!B12`（或 `行 42`）；Word → `段落 15`；JSON → `$.xxl.job.executor.retry`；文本 → `行 42`。
- 无法给出引用时标注「待确认」。

## 5. 功能需求

### P0（首个可用版本）

- **FR-01 选择来源**
  - **上传文件**：多选（Excel/Word/JSON/文本/ZIP），拖拽或文件选择；显示总量与文件数，超限拦截。
  - **扫描目录**：选择本地目录，可递归；按规则集筛选，展示命中/跳过。
  - **粘贴文本**：直接输入，走文本评审。
- **FR-02 扫描与解析**
  - 文件遍历、ZIP 解压、文档解析在后台工作线程执行；发现阶段显示动态进度，解析阶段显示实际计数与百分比，支持取消并在切换页面后继续显示进度。
  - 大清单分页渲染；扫描与评审互斥，避免工作区冲突。
  - 解压 ZIP 到工作区；目录遍历；生成文件清单（名称/类型/大小/评审模块/命中条件/输出格式/分块数/状态）。
  - 解析 Excel/Word/JSON 为可评审文本；解析进度条；按 4.1 边界处理。
  - 文件可手动勾选「分析 / 跳过」；点击预览解析文本；显示分块预估。
- **FR-03 评审模块与文件匹配**
  - 评审模块集中配置名称、颜色、文件匹配条件；支持新增、编辑、删除及持久化。
  - 匹配条件只指向模块，不再独立选择模板。条件支持完整文件名、关键字、后缀及 glob；可启停、按全局顺序调整优先级，第一条启用命中生效。
  - 未命中文件跳过；粘贴文本直接选择模块。
  - 升级时保留旧多规则集为文件匹配方案；存在不同模板绑定时拆成独立模块，未绑定模板转为独立模块，共享模板复制隔离。
- **FR-04 模块评审规范**
  - 输入说明、评审要求、输出格式及输出补充要求共同定义规范，程序填入文件正文并校验返回结构。
  - 每个模块独立编辑规范；内置规范可恢复。保存后扫描与评审采用当前模块规范，删除后重启不复活。
- **FR-05 评审配置**
  - 输出格式由模块配置：标准结论 / 检查表 / 简洁摘要 / JSON；任务页只读展示。
  - 分析粒度：逐文件 / 逐文件 + 按模块汇总 / 同模块合并评审；跨模块合并明确拒绝。
  - 分块参数、并发数（默认 3）、超时、自动重试（默认 1 次）。
- **FR-06 执行分析**
  - 发送前「确认数据去向」。
  - 统一分析单元队列，并发 3；流式输出；进度条（完成/总数/失败）。
  - 单文件/单块失败隔离；可重试失败项、可取消；分块结果按序合并。
- **FR-07 结果**
  - 每文件：结论（通过/有条件通过/阻断/失败）+ 依据/风险/整改项 + 结构化引用；分块文件标注「基于 N 块合并」。
  - 按模块分组展示与统计；每模块一份 LLM 汇总。
  - 标准格式校验结论与依据/风险/整改项；JSON 校验合法性。
- **FR-08 导出（简单版）**：列 `评审模块 | 文件路径 | 文件类型 | 命中规则 | 结论 | 引用 | 时间`；格式 Excel、结构化 JSON、Markdown、HTML。
- **FR-09 历史**：任务与文件级结果入库；保存规则集与模板 Prompt 快照；查看 / 重评 / 删除 / 搜索 / 导出。
- **FR-10 安全**：API Key 用 Windows DPAPI 加密；不落明文、不进日志/导出。
- **FR-11 内网适配**：允许内网 HTTP；超时 / 代理可配置。

## 7. 非功能需求

- **NFR-01 平台**：Windows 10/11 x64。
- **NFR-02 容量**：不限制文件数量；单文件上限可配置（默认 1.2 GB）；并发 3（可调）。
- **NFR-03 性能**：大批量文件清单分页，解压、解析和评审显示已完成 / 总数；大文件分块不阻塞 UI。
- **NFR-04 安全**：Key 加密存储；发送前明确数据去向；不写日志/导出。
- **NFR-05 稳定性**：单文件/单块失败隔离；支持取消与重试；工作区任务结束清理。
- **NFR-06 可维护性**：模板/规则/解析器/分块策略数据化、可扩展。
- **NFR-07 可观测**：本地脱敏调试日志，可开关。

## 8. 数据模型

- `task`：id、created_at、source_type、source_ref、rule_set_id、rule_set_snapshot、template_snapshot、granularity、model、status、stats。
- `task_file`：id、task_id、path、name、type、size、system、rule_id、template_id、parse_status、chunk_count、analyze_status、verdict、result_text、citations_json、error、duration_ms。
- `task_chunk`：id、file_id、index、char_count、status、result_text、error。
- `system_summary`：id、task_id、system、summary_text、stats。
- `template`：id、name、content、input_instructions、output_instructions、output_format、builtin、overridden。每个评审模块唯一拥有一份规范。
- 配置 schema_version=2；旧字段 system/template_id 保留用于历史兼容，规则 template_id 由模块派生。
- `rule_set` / `rule`：id、name、pattern、system、template_id、enabled。
- `settings`：base_url、model、allow_http、concurrency、timeout、max_file_size、chunk_threshold、chunk_size、retry_count、history_retention。

### 2026-10-13 定时自动评审补充

- 定时间隔由用户设置（分钟），可选 Git 拉取后扫描本地目录并自动按模块逐文件评审，结果保存历史。
- 默认仅资料内容或评审配置变化时调用模型。任务支持立即执行、启停、取消、修改和删除；删除计划保留评审历史。
- 关闭窗口隐藏到托盘继续运行；完全退出后停止。应用内任务串行，间隔从每轮结束后计算，重启不补跑所有错过的轮次。
- Git 拉取限快进，不自动处理本地修改或分叉；错误、超时和取消应可见。
- 移除最大文件数量配置与扫描上限，保留单文件/ZIP体积保护；忽略 `.git`。已知总数时明确显示例如 `400 / 589`，发现阶段显示累计数量。
